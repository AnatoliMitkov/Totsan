# Totsan workspace guidance

For any UI or UX change, read [the UI/UX principles](docs/ui-ux-principles.md) before editing components or styles.

Keep the existing product visual direction unless the task explicitly asks to change it. Treat Figma or an approved screenshot as the product-specific visual reference; use the principles guide to improve hierarchy, responsiveness, readability, and accessibility rather than to replace the approved layout.

Before handing off a visual change, check the relevant desktop and mobile states, keyboard focus, overflow, empty/error states where applicable, and the primary action hierarchy.
